# Задание 1. Анализ и планирование

*Чтобы составить документ с описанием текущей архитектуры приложения, можно часть информации взять из описания компании условия задания. Это нормально.*

### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут включать/выключать отопление.
- Пользователи могут устанавливать желаемую температуру отопления.
- Система поддерживает установку состояния дома в целом.
- Пользователи могут задавать расписание включения
- Пользователи имею доступ к своему дому
- Пользователи могут предоставлять доступ другому пользователю

**Мониторинг температуры:**

- Пользователи могут отслеживать фактическое значение температуры.
- Система поддерживает отслеживание состояния в целом.
- Система отслеживает работоспособность устройств
- Система шлет уведомления о событиях разной степени важности
- Пользователи могут наблюдать котельную и следить за системой отопления в доме

### 2. Анализ архитектуры монолитного приложения

*Перечислите здесь основные особенности текущего приложения: какой язык программирования используется, какая база данных, как организовано взаимодействие между компонентами и так далее.*

Приложение построено на основе технологий фреймворка Spring Framework, из которого использованы компоненты:
* Spring Boot для запуска встроенного веб-сервера и добавления конфигураций по-умолчанию
* Spring MVC для организации REST-сервиса
* Spring Data для изолирования доступа в БД

Среди других используемых технологий можно выделить:
* Язык программирования - Java
* База данных - PostgreSQL
* Система сборки и управления зависимостями - Maven

Из архитектурных особенностей можно выделить:
*Классическая монолитная архитектура, разделенная на несколько слоев
*Синхронное межслойное и межкомпонентное взаимодействие

Слои приложения
- **controller** - REST контроллеры для обработки запросов
- **service** - слой бизнес-логики
- **repository** - набор классов и методов для доступа в БД
- **entity** - классы, о объектный доступ к таблицам БД
- **dto** - классы, описывающие форматы данных при взаимодействии с другими системами

### **4. Проблемы монолитного решения**

- ограниченная возможность масштабирования  
- сильная связность кода между компонентами/слоями
- сложность поддержки и внесения изменений
- сложность внедрения нового функционала
- сложность распределения задач в команде

*Если вы считаете, что текущее решение не вызывает проблем, аргументируйте свою позицию.*

Текущая реализация имеет право на жизнь при условии:
 - умеренная нагрузка на систему и хорошая оптимизация
 - разработка одним или двумя программистами
 - слабая эволюция системы
 - отсутствие команды эксплуатации
